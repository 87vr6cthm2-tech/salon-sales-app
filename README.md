# SALON NOTE

店舗・スタッフ別の月次実績。既存のGitHub Pages上で動作し、売上の平文と秘密鍵は公開リポジトリに保存しません。追加のサーバー契約は不要です。

## iPhoneで初回だけ行うこと

1. Safariで既存のSALON NOTEを開き、再読み込みします。「暗号化同期 v12」が目印です。
2. 既に実績がある場合は「全実績バックアップ」を保存します。
3. 「初回設定・公開鍵を表示」を押します。
4. 表示された **公開鍵だけ** をChatGPTに送ります。
5. 「秘密鍵バックアップ」を押し、iPhoneの「ファイル」など安全な場所に保存します。秘密鍵はChatGPT・GitHub・スタッフへ送らないでください。
6. ChatGPT側で公開鍵の登録と初回の暗号化配信が完了した後、SALON NOTEを開くと実績が反映されます。

秘密鍵バックアップは別途必要です。「全実績バックアップ」には秘密鍵は含まれません。初回設定時に既存の同期鍵がある場合はその鍵を再利用します。

## 毎月の運用

この開発に続くChatGPT Workの会話へ「店舗売上分析」「スタッフ別実績」のExcelをアップロードします。GitHubへの書込み権限があるChatGPTが、このリポジトリのAGENTS.mdに従い変換・暗号化・配信します。SALON NOTE側でExcelを選び直す必要はありません。

**単に任意の会話へ添付しただけでバックグラウンド処理を起動するサービスではありません。** この会話の取込指示とGitHub接続が必要です。同期先の公開鍵の登録が済むまでは配信できません。

アプリを開いた時、画面に戻った時、オンライン復帰時、画面表示中の約60秒ごとに同期します。閉じている間にiOSのバックグラウンドで実行する仕組みではありません。GitHub Pagesへの反映待ちが発生する場合があります。

既存値と違う数値は自動上書きしません。相違一覧を確認して「反映」または「見送り」を選択します。見送りは更新全体（新規月も含む）を破棄する操作です。通常の新規月・空欄への追加と同一データの再送には操作不要です。

## データの扱い

- 店舗ID・年・月・担当者で識別し、別店舗・別年の実績を混ぜません。
- 店舗は月末締め、スタッフは15日締め。両者を一致させるための補正はしません。
- 店舗Excelの `YYYY年` とスタッフExcelの `YYYY年売上/再来率/再来店率/客数/失客数/次回予約率` に対応します。
- 同じ表の既知の月見出しを使用し、空欄や未来月の客数数式だけのゼロは未登録として扱います。実入力の0は保持します。
- 過去スタッフも該当年に保持します。2026年の表示順は木村・山岸・中村・藤野・関根です。
- 次回予約率、店販比率、客単価、再来店率、失客数を表示。資料にない値は未登録です。
- 「技術」の指名売上としての意味と税込・税抜区分は従来どおり未確定のため、画面の暫定表記を残しています。
- 店販比率は店販÷総売上。店販を総売上へ二重加算しません。再来率の平均は登録月の単純平均です。
- 既存v2形式を読み取り、元のデータ・集計情報を `legacy` に残します。保存前に直前の全データを端末内のrollbackキーへ保存し、それに失敗すると本体も更新しません。
- JSON復元も追加方式です。競合するバックアップで全履歴を置き換える操作は実装していません。

## 安全性と限界

受信端末ごとのRSA-OAEP SHA-256（3072bit以上）とAES-256-GCMで暗号化します。公開されるのは暗号文、鍵の識別子、更新番号とハッシュだけです。暗号文の大きさや更新回数は公開情報になります。

更新は削除しない履歴として保存し、未受信分を順番に適用します。ハッシュ、暗号認証、宛先、連番、直前ハッシュを検証します。重複、順序不正、改変、端末で確認済みの履歴の巻き戻しを拒否します。GitHub配信元そのものの信頼はGitHubアカウントと書込み権限に依存し、独立した送信者署名はありません。

秘密鍵・復号済み実績はSafariのlocalStorageに保持します。共有端末で使わないでください。端末を操作できる人からデータを隠すログイン機能ではありません。Safariのデータ消去やプライベートブラウズで失われる可能性があります。管理者の鍵をスタッフへ共有すると、管理者宛ての全実績を読めるため共有しないでください。

メイン画面は外部JavaScriptを読み込まず、CSPで同一サイトのスクリプトに限定しています。予備の手動Excel取込のみ、保存データ・秘密鍵へアクセスできないsandbox iframe内でSheetJS 0.20.3を使います。外部ライブラリの入手先は https://docs.sheetjs.com/docs/getting-started/installation/standalone/ 。通信できない場合はChatGPT側の取込を利用してください。

端末変更時は同じサイトで「秘密鍵を復元」からバックアップを選びます。その後、暗号化履歴を先頭から読み直せます。ローカルだけで追加した記録やメモは別途バックアップが必要です。鍵を失った場合の復号はできません。

## 開発・送信処理

Node.js 22以上、Python 3とopenpyxlを利用します。ブラウザ側はビルド不要です。Pythonは読み取り専用でExcelを変更しません。

```sh
node --test tests/sync.test.cjs
node tests/dashboard-smoke.cjs
node tests/real-workbooks.cjs /private/store.xlsx /private/staff.xlsx
node scripts/prepare-sync.cjs --public /private/public.json --store funabori --out /private/encrypted --manifest /private/manifest.json /private/store.xlsx /private/staff.xlsx
```

初回のみ `--manifest` を省略します。以後はGitHub上の最新manifestを取得して渡します。出力先はリポジトリ外を強制します。出力される暗号文 `<hash>.json` と `manifest.json` だけを `sync/<keyId>/` に追加し、既存履歴は削除しません。古いmanifestで新しい履歴を消さないよう、取得時点のブランチSHAを条件に1つのcommitで公開します。競合時は最新manifestを取り直して作り直します。

`daily.html` は旧日別アプリで、月次実績とは別保存です。今回の日次データの移行・同期は対象外です。検証範囲はTEST-RESULTS.mdを参照してください。
